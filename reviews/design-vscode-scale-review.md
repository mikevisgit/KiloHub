# Соразмерность двух макетов интерфейсу VS Code

## Основание и измерения

Пользователь запросил перенести понравившуюся соразмерность иллюстрации в оба существующих дизайна и требования, сохранив композиции. Прочитаны текущие UX/ТЗ, оба HTML и общие стили/генератор/JS, просмотрены [реальный screenshot Step1](../desing/screenshots/kilo-hub-step1-scale-reference.png) и [imagegen-иллюстрация](../desing/screenshots/kilo-hub-inset-in-vscode-preview.png). Оба изображения сохранены без модификации.

| Наблюдение | Реальный Step1 | Иллюстрация |
| --- | --- | --- |
| Полный размер изображения | 2539×1445 | 1662×946 |
| Ширина sidebar, приблизительно | 700 imagepx | 459 imagepx |
| Шаг обычных строк | 38–39 imagepx | 25–26 imagepx |
| Нормализованный шаг/ширина | около5,5% | около5,5% |

Размеры строк дополнительно измерены независимым агентом по полосам glyph исходника836–852/875–891/913–929/952–968. Высота glyph не равна font-size или line-height. Imagegen сжал общий масштаб примерно0,655× и перерисовал текст: его пиксели не задают точный CSS. DPI/zoom неизвестны. Измерения подтверждают направление «умеренный акцент имени, читаемый основной текст», а не дают pixel-perfect спецификацию.

## Изменение размеров

Раньше в исходных монограммах были заголовок24px, имя20px, знак51px при действиях/диалогах12px; в рамках имя17px и знак34px. Главная диспропорция — крупные имена/знаки одновременно с уменьшенным рабочим текстом.

Теперь база `B=var(--vscode-font-size,13px)`, семейство `var(--vscode-font-family,'Segoe UI',Arial,sans-serif)`, обычное начертание `var(--vscode-font-weight,400)`. Это UI-font, не editor.fontSize. [Исходник VS Code WebviewThemeDataProvider](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/webview/browser/themeing.ts) экспортирует UI-переменные family/weight/size отдельно от editor-font; на проверенной версии main UI-size13px и weight normal. Fallback13px выбран для автономного стенда; неизвестные DPI/zoom пользователя из этого не выводятся.

| Элемент | Тонкие рамки, B13 | Исходные монограммы, B13 |
| --- | --- | --- |
| Основной текст действий/диалогов/tooltip | 13px | 13px |
| Вторичные метки/даты | 12px | 12px |
| Заголовок списка | 14px | 15px |
| Имя папки | 15px | 16px |
| Квадрат / буквы монограммы | 32 / 13px | 36 / 15px |
| Padding плашки вертикаль/горизонталь | 8 / 10px | 11 / 12px |
| Интервал карточек и знак–имя | 8px | 10px |

Увеличение имени рамок1,154×; монограмм1,231× — немного свободнее измеренного ориентира ради сохранения выбранного направления. Знаки2,462B/2,769B; основные команды имеют минимальную высоту28/13B и растут при переносе. Вместо жёсткой высоты карточки применяется содержимое: при B13 обычная свёрнутая строка с именем/датой около57px у рамок и64,5px у монограмм, текущая дополнительно включает подпись. Это арифметика line-height и padding, не измерение рендера.

`scale.css` подключён после двух общих CSS во всех7 темах. Прежние фиксированные product font-size удалены из исходных стилей, в том числе узких media-правил. Размеры галереи/поясняющих подписей за пределами `.panel` не являются интерфейсом расширения. Геометрия исходных округлых карточек/пастельных знаков сохранена; рамки остаются компактнее. Цветовые токены и JS неизменны.

## Проверки и границы доказательств

- `node desing/variants/build-final.mjs` пересобирает оба HTML; ровно2 композиции/7тематических представлений.
- `node desing/variants/verify-scale.mjs` проверяет общие tokens/fallback, отсутствие фиксированных product font-size, порядок подключения, ellipsis/переносы, арифметику ширин260/320/400 при B13/16/20. При260/B13 остаётся≈138px для имени рамок и122px для имени монограмм; при260/B20 —≈83,6/59px. Условный запас17px под scrollbar не является измерением системного scrollbar. Положительная ширина не доказывает визуальную красоту переносов.
- `verify-final.mjs` и `verify-regressions.mjs` проходят: ссылки/темы/контраст,35путей, даты, очереди раскрытия, tooltip handlers. Анимация320мс/reduced motion и исправления предыдущего аудита сохраняются.
- При недостатке высоты — прокрутка, а не уменьшение текста. Реальные260px/масштаб200%, screen reader, пользовательские шрифты/темы и соответствие скриншоту требуют ручной приёмки: браузерный fileURL запрет соблюдён. Ни один из этих runtime-пунктов здесь не объявлен проверенным.

Точные правила перенесены в [UX пункт24](../desing/UX%20правки.md) и [финальное ТЗ](../desing/ТЗ%20реализации%20дизайна%20VSIX.md). Production, VSIX и данные Kilo не менялись.

Независимый агент повторно проверил каскад scale.css: существенных несоответствий не обнаружил; старые .monograms/.inset/media значения перекрываются. Дополнительно учёл viewport260→панель244 после полей галереи, scrollbar17 и двойную contrast-рамку: при B20 у монограмм остаётся около41px для текста. Это дополнительная арифметика, не браузерная проверка.
