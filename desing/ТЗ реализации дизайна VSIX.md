## Полное поведение и точные тексты

1. Заголовок **«Мои папки с Kilo»**. Рядом небольшой значок информации с подсказкой: **«Здесь собраны папки, в которых вы работали с Kilo. Чтобы вернуться к работе, выберите папку и откройте её.»** Постоянного пояснения нет.
2. Refresh — только **↻**, доступное имя и подсказка **«Обновить список папок и диалогов из Kilo»**. Чтение при первом открытии и вручную; автоматическое наблюдение не добавлять.
3. Текущая папка, если включена по Kilo-истории, всегда первая. Подпись **«Вы сейчас здесь»** и устойчивый визуальный акцент независимы от раскрытия. Открытая в VS Code папка без Kilo-истории сама по себе в список не добавляется.
4. Нажатие плашки, в том числе названия, только раскрывает/сворачивает детали. Название и инициалы узнаваемы; название важнее даты. Полный путь только в единой подсказке всей .folder-head при наведении мыши, отдельной строки пути нет. Имя, знак, дата, current/missing и стрелка внутри плашки не являются отдельными владельцами tooltip; переход между ними не перезапускает показ. Правило одинаково для свёрнутого/раскрытого состояния. Одинаковые имена различаются через эту подсказку; новой функции не добавлять.
5. Действия в раскрытых деталях: **«Открыть в этом окне»** — подсказка **«Выбранная папка откроется вместо текущей в этом окне VS Code»**; **«Открыть в отдельном окне»** — **«Текущая папка останется открытой»**; **«Показать файлы папки»** — **«Откроется Проводник Windows»**. Последние два действия второстепенны. Постоянных пояснений нет. У доступной текущей папки обе команды «Открыть…» отсутствуют в DOM и Tab-порядке; остаётся только второстепенное «Показать файлы папки». У доступной нетекущей папки показаны все три команды.
6. Блок **«Последние диалоги»**: подсказка **«До трёх последних диалогов. Открыть и продолжить их можно в Kilo Code»**. До трёх названий от нового к старому, каждое с новой строки, плотные интервалы, без маркеров, дат, кнопочных рамок, подчёркивания, hover-подсветки и постоянного пояснения. Одна строка, многоточие, полное название в доступной подсказке. Это пассивный текст, Enter не открывает диалог. Пустой title — «Без названия» по существующему defensive fallback.
7. Недоступная папка остаётся в истории: одна видимая пометка **«Папка не найдена»**, без отдельной подсказки статуса; плашка показывает только полный путь. Не повторять предупреждение внутри. Все три действия отсутствуют в DOM и Tab-порядке; контейнер действий и место под него не создаются. История начинается сразу, без разделителя и отступов от отсутствующих кнопок. Это правило приоритетнее текущей папки, если оба состояния совпали; диалоги и подсказки сохраняются. Это уточнение Step 2 заменяет прежнее отображение disabled-кнопок, не меняя исторический Step 1.

## Даты и сортировка

Источник — последняя достоверная Kilo-активность папки, а не время открытия папки. Относительная дата видна на свёрнутой плашке рядом с названием и сохраняется при раскрытии. Подсказки даты нет ни в свёрнутом, ни в раскрытом состоянии.

Сначала отбрасывать отсутствующий, некорректный или будущий timestamp (включая позже текущего момента сегодня): **«Дата неизвестна»**. Не выдумывать дату. Для достоверного timestamp считать разность календарных дат в локальном часовом поясе, не полные 24 часа; переходы летнего времени не меняют число календарных дней.

| Дней | Отображение |
| --- | --- |
| 0 | Сегодня, чч:мм — 24-часовой формат |
| 1 | Вчера |
| 2–6 | N дня/дней назад |
| 7–13 | Неделю назад |
| 14–20 | 2 недели назад |
| 21–29 | 3 недели назад |
| 30–59 | Месяц назад |
| 60–364 | floor(дни / 30) месяцев назад |
| ≥365 | floor(дни / 365) лет назад; 1 — «Год назад» |

Склонение: последние две цифры 11–14 → дней/месяцев/лет; иначе последняя цифра 1 → день/месяц/год, 2–4 → дня/месяца/года, остальные → дней/месяцев/лет. Месяцы и годы приблизительные; точный timestamp используется для сортировки, отдельный tooltip даты не показывается. Время в видимой подписи — только сегодня. При актуализации отображения учитывать смену локального дня; это не дополнительное чтение БД.

После текущей папки: достоверные даты по убыванию точного timestamp, неизвестные после известных по имени. При равных датах — имя, при равных именах — стабильный нормализованный путь/ID. Диалоги также по timestamp, неизвестные после известных, затем title и ID. Отображаемый текст относительной даты не использовать для сортировки. Простое открытие не меняет активность. Полный список папок сохраняется, сокращаются только показанные диалоги.

## Аккордеон, движение, клавиатура

Принято по команде выполнить все правки: одновременно раскрыта не более одной папки; повторное нажатие сворачивает её, нажатие другой сворачивает предыдущую. Плавное раскрытие/сворачивание длительностью **320 мс**, вдвое медленнее первоначальных 160 мс. Быстрые повторные нажатия сохраняют последнее намерение пользователя, включая сворачивание повторным нажатием. При изменении высоты компенсировать прокрутку относительно выбранной плашки, по возможности не уводить её из-под курсора. Если начало деталей вне видимой области — только минимальная необходимая прокрутка, без прыжка наверх. Край списка ограничивает компенсацию; нельзя гарантировать невозможное удержание координаты. При reduced motion движение отключить, компенсацию положения сохранить.

Плашка доступна по Tab, Enter/Space управляют раскрытием; aria-expanded и aria-controls согласованы с деталями. Скрытые детали исключены из порядка фокуса. После сворачивания не оставлять фокус внутри скрытого блока. Все команды имеют доступные имена и видимый focus. Tooltip закрывается Escape, длинный текст переносится в пределах CSS max-width330px без подгонки позиции к viewport. Подсказки кнопок и длинные информационные подсказки различаются по правилам ниже. Пассивные названия не имеют роли кнопки; фокус не показывает tooltip. Не полагаться на цвет для текущего/missing. В узкой панели нет горизонтальной прокрутки, длинное имя папки переносится, диалог сокращается. Проверить 260/320/400 px и масштаб 200%.

## Единое поведение всех подсказок (UX27–28)

Последнее уточнение «как и везде» отменяет исключения длинных подсказок. Любой tooltip появляется только при hover источника; выход с источника немедленно скрывает popup без120мс. Все popup pointer-events:none/tabIndex−1: переход поверх них не удерживает показ, pointer/click проходят к элементам под ними. Focus/Tab не показывают и не удерживают, Escape скрывает и очищает aria-describedby. Кнопки, аккордеон, aria-label/role и focus-outline сохраняют клавиатурную функциональность.

Это одно правило для полного пути .folder-head, команд папки, refresh/info, заголовка истории и названий диалогов. Отдельные типы data-tip-kind и учёт модальности не нужны. Внутри одного owner переход между потомками не переписывает текст, не скрывает popup и не запускает таймеры. На плашке единственный owner полного пути; у даты и missing нет собственных tooltip. При переходе к следующему owner связь aria-describedby старого снимается. Чужая панель не становится владельцем. Контент popup только текст.

Позиция exact `left=owner.left`, `top=owner.bottom`, без viewport-clamp/JS max-size. CSS `width:max-content;max-width:330px;height:auto;max-height:none;overflow:visible`: текст переносится и растёт по содержимому, не создаёт требующую мыши прокрутку. Читать длинный текст можно, пока курсор остаётся на источнике. Scroll/resize пересчитывают якорь без подгонки. Задержка600мс, перенос над действиями и новый UI не добавляются.

Выход за видимую область и возможное обрезание — принятый компромисс. DOM-popup внутри Webview/iframe не может перекрыть соседний UI VS Code за границами своей поверхности; host-tooltip/отдельная поверхность сейчас не реализуется. Не выдавать исходниковую проверку за фактический browser hit-testing или визуальную приёмку.

## Соразмерность UI VS Code

**Полная нормативная размерная спецификация:** [все размеры, отступы, типографика и ограничения двух эталонов](design-size-spec.md). Приложение является частью этого ТЗ; таблица ниже — краткая сводка. При реализации использовать также подробные правила каскада, content-dependent высот, tooltip и отличий контрастной темы из приложения.

Принято по сопоставлению [реального Step 1](screenshots/kilo-hub-step1-scale-reference.png) и [иллюстрации замены секции](screenshots/kilo-hub-inset-in-vscode-preview.png). Первая картинка 2539×1445, вторая 1662×946. Отношения размеров внутри каждой картинки значимы; их пиксели не являются CSSpx и не определяют DPI/zoom редактора. Imagegen — композиционный ориентир, не техническое измерение рендера.

Единая база **B = `var(--vscode-font-size, 13px)`**, семейство `var(--vscode-font-family, 'Segoe UI', Arial, sans-serif)`, обычное начертание `var(--vscode-font-weight, 400)`. Размеры определяет последний общий файл `scale.css`, подключённый в обоих HTML; демо-палитры не переопределяют B. При интеграции не подменять базу шрифтом редактора кода (`editor.fontSize`). Имена/заголовки — 600, буквы крупных монограмм — 700; обычный текст сохраняет UI-weight.

| Элемент | Тонкие рамки | Исходные монограммы | При fallback B=13px |
| --- | --- | --- | --- |
| Заголовок Kilo Hub, действия, диалоги, tooltip, статус | 1B | 1B | 13px |

| Буквы монограммы | 1B | 15/13B | 13 / 15px |

| Интервал карточек и знак–имя | 8/13B | 10/13B | 8 / 10px |

Line-height: имена и заголовок списка 1,3; обычный текст/даты/действия 1,4; диалоги 1,55; tooltip 1,45; буквы знака 1. Padding действий — 4/13B вертикально и 8/13B горизонтально. Диалоги не разделять дополнительными вертикальными полями. Начертание и умеренные размеры имени выделяют папку, а не уменьшают окружающий текст. У «Монограмм» сохраняются округлые карточки/цветные знаки в оригинальной палитре, у рамок — компактные тонкие границы. Толщина рамок, контуры фокуса и форма углов остаются отдельными стилевыми величинами, а не компенсацией DPI.

На ширине панели 260/320/400 CSSpx не вводить media-уменьшение шрифтов/знаков. `min-width:0` у текстовой области, перенос длинного имени папки, однострочный ellipsis диалога, перенос текста кнопок и вертикальная прокрутка при нехватке высоты. Высота 790px в локальном стенде — только рамка просмотра, в Webview использовать доступную высоту секции и не отнимать место у соседнего Explorer. При zoom не вводить inverse-scale или дополнительные коэффициенты DPI. Проверить baseline 13/16/20px и 200% zoom в реальном окружении; статическая арифметика ширин не заменяет рендер.

## Темы и состояния

Компоненты используют `--vscode-sideBar-background`, `--vscode-sideBar-foreground`, `--vscode-descriptionForeground`, `--vscode-sideBar-border`, `--vscode-list-inactiveSelectionBackground/Foreground`, `--vscode-badge-background/foreground`, `--vscode-button-background/foreground`, secondary и hover варианты, `--vscode-focusBorder`, `--vscode-contrastBorder`, `--vscode-contrastActiveBorder`, `--vscode-disabledForeground`, `--vscode-editorWarning-foreground`, `--vscode-font-family` с fallback. [Официальное описание Webview и тем](https://code.visualstudio.com/api/extension-guides/webview#theming), [справочник цветов](https://code.visualstudio.com/api/references/theme-color). В интеграции не подключать `demo-themes.css`: значения поставляет редактор. Оригинальная пастельная палитра монограмм — визуальный reference; в текущей теме использовать контрастные семантические цвета, не принудительную светлую тему. Проверять реальные dark/light/high contrast и изменение темы без перезагрузки. Текст минимум 4,5:1, крупный текст 3:1; важные границы/focus минимум 3:1. Не подавлять forced colors.

Состояния сохраняют понятный статус, не расширяют продукт:

- Первое чтение: «Загружаем папки…», aria-busy; блокировать повторный refresh.
- Успешный пустой список: «Здесь пока нет папок с диалогами Kilo». Refresh доступен; не предлагать ручное добавление.
- Обновление: предыдущий список остаётся, «Обновляем список…», aria-busy; исключить параллельные запросы.
- Ошибка первого чтения: «Не удалось загрузить папки. Попробуйте обновить список». Технические детали — Output Channel Kilo Hub.
- Ошибка refresh: прежний список остаётся, «Не удалось обновить список. Показаны ранее загруженные данные». Не выдавать его за свежий.
- missing: по правилам выше; это не ошибка всего источника. При успешном refresh исчезнувшие sessions и опустевшие папки удаляются из представления.

Эти состояния обязательны будущей реализации; основной HTML показывает нормальный список и missing, не имитирует подключение к БД.

## План интеграции для следующего агента

1. Прочитать AGENTS, план, handoff, нормативную модель Step 1 и это ТЗ; получить выбор одной из двух композиций. До выбора production не менять.
2. Сохранить существующие discovery, нормализацию путей, schema guard, WAL/SHM/busy handling, read-only SQLite и команды. Только metadata обычных неархивных root sessions (`parent_id IS NULL`, `time_archived IS NULL`); не читать тела сообщений, файлы проектов, не изменять kilo.db. Поддержка локальных Windows путей остаётся; не добавлять UNC/Remote/WSL/Dev Container/.code-workspace.
3. Заменить TreeView выбранным WebviewView в том же контейнере, передавать минимальную DTO из host. Webview не получает доступ к БД. Локальные ассеты через asWebviewUri, строгая CSP, без внешних ресурсов, inline script и eval. Не вставлять имена/path/title как сырой HTML; textContent/экранирование. Демонстрационный код не копировать вслепую как production.
4. Разрешить сообщения только refresh и три действия с проверенным ID папки. Host заново проверяет принадлежность текущему snapshot, доступность пути и тип сообщения. Не исполнять произвольные команды/пути из Webview. Open Here → vscode.openFolder forceReuseWindow; отдельное окно → forceNewWindow; Проводник — существующий проверенный адаптер VS Code.
5. Сохранить локальность, отсутствие телеметрии/сети/LLM/реестра/ручного управления. Не добавлять поиск, избранное, копирование пути, preview или открытие диалогов. Сохранять раскрытый ID/focus при refresh, если папка существует; корректно сбрасывать при удалении. Больше 1000 диалогов не должно блокировать Extension Host.
6. Выполнить профильные unit/extension проверки, compile/lint, package, проверку состава VSIX и установку в изолированный профиль по процессу проекта. Только после реальной проверки заявлять поддержку тем и работающие команды.

## Устойчивые 16 цветовых групп значков

**Актуальное решение:** единая мягкая16цветовая система во всех семи тематических панелях, включая original. Предыдущее временное исключение original отменено; его понравившиеся пастельные заливки стали опорными для общей палитры. Обычные темы не имеют видимых рамок значков; рамки карточек сохраняются.

Принято в UX26. Цветовая группа относится только к монограмме/значку, не к карточке, названию или действиям. Один путь имеет одну группу в обеих композициях; current, missing, refresh, раскрытие и сортировка не входят в ключ. Настройки цветов, хранение таблицы соответствий и дополнительные команды не нужны. Цвет не является единственным признаком состояния.

### Нормализация и группа

Общий эталон — `variants/folder-colors.cjs`. В пределах текущего scope допускается только абсолютный локальный путь вида `D:\каталог`; UNC, namespace и относительные пути возвращают null, не получают вымышленного ID. Это не новая проверка доступности файлов и не расширение discovery Step1. В production использовать host-путь из существующего discovery и согласовать тот же ключ с его нормализацией.

1. Заменить `/` на `\`. Сохранить корень диска; повторные разделители и компоненты `.` пропустить, `..` снять предыдущий компонент. Выход выше корня отклонить.
2. Отклонить управляющие символы, `< > " | ? *`, двоеточие внутри компонента, компоненты с конечной точкой/пробелом. Не обрезать путь через trim и не разрешать его относительно cwd. Завершающие разделители вне корня удалить.
3. Привести весь ключ к нижнему регистру через JavaScript `toLowerCase()`. Unicode не нормализовать отдельно. Это регистронезависимый ключ текущего Windows-scope, не обещание идентичности case-sensitive каталогов.
4. FNV-1a по UTF-16 code units: начальное беззнаковое h=2166136261, на каждый `charCodeAt(i)` выполнить `h=Math.imul(h ^ code,16777619) >>> 0`; группа `h % 16` (0–15). Это устойчивое распределение, не уникальный идентификатор папки. Переименование/перемещение может изменить группу.

Полный путь для tooltip и цвета берётся из одного `data-path`/host DTO; отображаемое имя и позиция не хэшируются. Некорректный путь не получает цветовую группу; применяется нейтральный badge fallback. Отсутствующая на диске папка с корректным сохранённым путём сохраняет группу.

### Палитра и контраст

**Вразброс, но устойчиво:** после `slot=h%16` использовать фиксированную перестановку `slotOrder=[1,6,12,9,15,5,2,13,8,0,10,3,14,7,11,4]`; индекс цвета=`slotOrder[slot]`. Hue, светлая заливка и оттенок инициалов берутся по одному этому индексу. Состав16цветов не изменён. Перестановка одна для всех тем и дизайнов, не вычисляется заново при refresh.

Последовательность слотов0–15: персиковый → мятный → лавандовый → голубой → розовый → травяной → песочный → лиловый → бирюзовый → красноватый → синий → жёлтый → пурпурный → зелёно-мятный → индиго → лаймовый. Чередуются тёплые/холодные и разные семейства, как в исходном mint→peach→lavender→blue. У последовательных demo-слотов кратчайший разрыв hue не меньше60°, но это арифметический ориентир, не доказательство зрительной различимости.

Демонстрация раньше выглядела градиентом потому, что fixtures покрывали слоты0–15 по порядку, а палитра была спектральной. Переименование путей, смена дат и сортировка по цвету не нужны и не выполняются. Сохраняется current-first, затем реальная активность. Для произвольных соседних путей одинаковые/близкие цвета возможны: не перекрашивать папку вслед за её соседями. Эта однократная смена таблицы принята пользователем; дальнейшее соответствие остаётся детерминированным.

Индексы базовой палитры 0–15 имеют hue в градусах: **0,20,38,55,76,100,130,155,175,195,215,235,255,275,300,330**. Направления: красный, терракотовый, охристый, жёлтый, лаймовый, травяной, зелёный, мятный, бирюзовый, голубой, синий, индиго, фиолетовый, лиловый, пурпурный, розовый. Это группы оттенков, не обещание уникального зрительного распознавания.

Точные светлые RGB-заливки по индексам базовой палитры0–15: `#efd9d9`, `#f4deca`, `#eee1ca`, `#eee8ce`, `#e5e9d1`, `#dce8d0`, `#d3e9d9`, `#d1e9e1`, `#d2e8e7`, `#d5e7ed`, `#d8e3f1`, `#dde0f2`, `#e5ddf5`, `#eadcf0`, `#eedbed`, `#f0dbe4`. Peach/mint/blue/lavender точно сохраняют прежние исходные заливки; остальные подобраны близкими по мягкости. Это reference исходного эталона до d1ef061, расширенный до16групп.

В демо вычисляется фактический background панели через theme tokens; rgba композится с предками. Относительная sRGB-яркость>0,35 выбирает светлые заливки выше; иначе HSL(h,24%,28%). Инициалы HSL(h,28%,25%) в light или HSL(h,28%,90%) в dark. HSL округляется до RGB; если контраст инициалов к заливке<4,5:1, выбрать чёрный/белый с большим контрастом. Фон знака не зависит от current/missing и не обесцвечивается из-за статуса.

В обычных original/light/dark `--folder-border:transparent`: резерв1px внутри прежних размеров остаётся, видимой обводки нет. Контраст заливки к поверхности/рамки≥3 в этих темах не требуется. НЕ удалять рамки карточек, текущий акцент и текстовые пометки.

В HC-dark/HC-light читаемость приоритетна: если контраст заливки знака к фактическому фону плашки≥3:1, граница также transparent; иначе граница1px чёрная/белая с большим контрастом к поверхности. Режим распознаётся по demo-contrast либо классам/атрибуту theme-kind высококонтрастного Webview. Forced-colors использует Canvas/CanvasText и системную границу без подавления forced-color-adjust. Если computed цвет не поддерживается (не rgb/rgba), fallback Canvas/CanvasText, в обычном режиме граница transparent, в HC — CanvasText. Группа остаётся прежней. Реальное переключение тем и пользовательские темы проверять в VS Code отдельно.

Обработчик наблюдает изменения class/style/theme-kind у документа и предков, media forced-colors/color-scheme и возврат фокуса; пересчитывает оттенки без изменения path→group. В production проверить обновление реальной темы VS Code и произвольных пользовательских тем; локальные арифметические проверки не являются доказательством браузерной доступности. При нестандартных темах/нарушениях зрения группы могут восприниматься одинаково.

### Уточнение: попадание указателя в прямоугольник подсказки

Для всех tooltip при каждом pointermove внутри доступной поверхности проверить clientX/clientY по getBoundingClientRect видимого popup. Попадание внутрь или на границу прямоугольника немедленно скрывает его в том же событии, даже если pointer-events:none направил событие в лежащий под ним owner. Сам popup по-прежнему не перехватывает pointer/click.

После такого скрытия owner считается dismissed до настоящего ухода с него и нового входа; переходы между его потомками не возвращают popup. Новый отдельный owner может показывать свою подсказку. Escape сохраняет аналогичное подавление. Проверяется фактическая точка указателя, без прогнозирования траектории/таймера/кадровой задержки. За границей Webview события недоступны, прежние ограничения поверхности остаются.
