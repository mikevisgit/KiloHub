# Step 1: Kilo Activity Hub VSIX

## Краткий ответ

Step 1 — устанавливаемый VSIX, который показывает только папки, где были диалоги Kilo Code.

Структура интерфейса:

```text
KILO FOLDERS
▾ Project A
    D:\Projects\Project A
    Open Here
    Open in New Window
    Open in File Explorer
    Dialog title 1              19.09.2026 18:20
    Dialog title 2              18.09.2026 10:15
▸ Project B
```

В свёрнутом состоянии верхний уровень содержит только имена папок. Обычный клик раскрывает полный путь, три действия и отдельные строки связанных диалогов.

Папка без связанного Kilo-диалога в Hub не отображается. Пользователь не добавляет и не удаляет папки вручную: список полностью вычисляется из локальных данных Kilo.

После `Refresh` удалённая из Kilo session исчезает из Hub. Папка исчезает, если у неё не осталось других обычных root sessions.

Для открытия папки используется официальный built-in command `vscode.openFolder`:

- `forceReuseWindow` — открыть в текущем окне;
- `forceNewWindow` — открыть в новом окне.

## Объём первой версии

- отдельный локально устанавливаемый `.vsix`;
- раздел Kilo Hub в Activity Bar;
- нативное представление `Kilo Folders` с плоским верхним списком и раскрываемыми деталями;
- только папки, для которых найден хотя бы один Kilo-диалог;
- в свёрнутом состоянии только имя папки;
- в раскрытых деталях полный путь, действия и названия связанных обычных root-диалогов;
- дата последней активности рядом с названием диалога, если она доступна;
- defensive fallback `Без названия` для повреждённого пустого title с предупреждением в Output;
- ручное обновление списка из локального хранилища Kilo;
- открытие папки в текущем окне;
- открытие папки в новом окне;
- открытие папки в Проводнике Windows;
- понятная обработка удалённых или недоступных папок;
- только Windows и текущая локальная Kilo database/environment;
- Kilo Code 7.7.5 или новее в пределах подтверждённой совместимой schema;
- только локальные пути на дисках Windows, без UNC и remote URI;
- сборка и smoke test `.vsix`.

## Не входит в Step 1

- ручное добавление папок;
- ручное удаление или скрытие папок;
- отдельный реестр папок Hub;
- список VS Code `Open Recent`;
- summary и LLM;
- embeddings и semantic search;
- поиск по содержимому диалогов;
- Hub API, MCP или Kilo tools;
- открытие конкретного Kilo-диалога;
- архивные и дочерние agent sessions;
- `.code-workspace`, multi-root, Remote SSH, WSL, Dev Container и UNC-пути;
- автоматическое отслеживание изменений Kilo;
- legacy history из `globalStorage/kilocode.kilo-code/tasks/*.json`;
- индекс содержимого файлов проектов;
- облачная синхронизация.

## Ключевая зависимость

Переключение между папками технически подтверждено официальным VS Code API. Перед реализацией UI обязательно нужно исследовать локальное хранилище Kilo и подтвердить:

- где находятся диалоги;
- где хранится название диалога;
- подтвердить чтение `session.directory` как локального пути;
- можно ли безопасно читать работающую `kilo.db` из Extension Host;
- как повторно читать данные по ручной команде `Refresh`.

Для актуальной Kilo 7.7.5 связь хранится в `session.directory`. Step 1 читает metadata напрямую из локальной `kilo.db` в read-only режиме. Официальный Kilo CLI используется в Discovery только для сверки результата с `--max-count 10000` и не является runtime-зависимостью Hub.
