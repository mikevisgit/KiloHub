# Discovery Step 1

## 1. Что уже подтверждено

Официальная документация VS Code подтверждает built-in command `vscode.openFolder` с options:

- `forceNewWindow`: открыть папку в новом окне;
- `forceReuseWindow`: открыть папку в текущем окне.

При открытии в текущем окне VS Code завершает текущий Extension Host и запускает новый в выбранном workspace. Переключение выполняется одним действием, но является штатной сменой контекста окна.

Источник: [VS Code Built-in Commands](https://code.visualstudio.com/api/references/commands#_commands).

## 2. Главная задача Discovery

Нужно подтвердить способ получить из локальных данных Kilo следующий набор:

```text
session.id → session.title → session.directory → timestamps
```

Это обязательная зависимость Step 1. Данные VS Code `Open Recent` не решают задачу, потому что не доказывают наличие Kilo-диалога.

## 3. Что исследовать в Kilo

### 3.1 Физическое хранение

- путь к данным Kilo на Windows;
- путь к текущей локальной Kilo database/environment и правила его переопределения;
- меняется ли расположение в portable mode;
- как подтвердить отсутствие deleted tombstones: удалённая session должна исчезать из выборки.

Legacy task-файлы `globalStorage/kilocode.kilo-code/tasks/*.json` не исследуются как источник Step 1. Поддерживается `kilo.db` из Kilo Code 7.7.5+ при совместимой schema.

### 3.2 Схема диалога

- `session.id`;
- сохранённый title;
- created/updated timestamps;
- `parent_id` и `time_archived` для фильтрации root non-archived sessions;
- обязательный `session.directory` как связь с папкой;
- наличие записей без title или без связи с папкой;
- возможные дубликаты.

### 3.3 Связь с папкой

- соответствует ли `session.directory` фактическому локальному пути;
- можно ли восстановить путь после закрытия папки;
- как кодируются Windows paths и URI;
- как распознать и исключить `.code-workspace`;
- что происходит после перемещения проекта;
- как распознать и исключить WSL, SSH, Dev Container и UNC contexts.

### 3.4 Доступ из другого расширения

Для Step 1 выбран прямой read-only доступ к локальной `kilo.db`. Нужно проверить:

1. корректное определение пути с учётом `KILO_DB`, `XDG_DATA_HOME` и channel/environment overrides;
2. SQLite-библиотеку, совместимую с Extension Host и Windows VSIX packaging;
3. read-only/WAL semantics, busy handling и concurrent access;
4. schema/version guard до выполнения запроса;
5. metadata-only запрос к таблице `session` без чтения сообщений.

Официальный `kilo session list --all --max-count 10000 --format json` используется только как oracle для сравнения результатов. Фиксированный лимит 10 000 достаточен для Step 1 и не увеличивается автоматически. Отдельный Kilo CLI не является runtime-зависимостью. Private bundled server или executable VS Code-расширения не используются как контракт.

### 3.5 Безопасность чтения

- можно ли читать источник при работающем Kilo;
- нужен ли read-only SQLite connection или snapshot;
- возможны ли file locks и partial writes;
- как обрабатывать неизвестную версию схемы;
- может ли чтение влиять на производительность Kilo;
- какие пользовательские данные кроме title/path присутствуют и как их не загружать без необходимости.

### 3.6 Обновление данных

- как безопасно выполнить повторное чтение по команде `Refresh`;
- когда title становится доступен и может ли меняться;
- как повторное чтение обнаруживает новую session и отсутствие удалённой session.

## 4. Минимальный исследовательский прототип

Spike должен быть временным Extension Development Host прототипом с тем же SQLite runtime, который планируется упаковать в `.vsix`.

Он должен:

1. найти storage текущей изолированной тестовой Kilo environment;
2. извлечь несколько обычных реальных диалогов из этой же изолированной `kilo.db`;
3. вывести только `session.id`, `session.title`, timestamps и `session.directory`;
4. сгруппировать диалоги по папке;
5. исключить папки без диалогов;
6. корректно пережить работающий параллельно Kilo;
7. повторить проверку после создания, переименования и удаления session;
8. повторить проверку после перемещения или удаления папки.

Spike не должен изменять storage Kilo.

## 5. Критерий выбора интерфейса

SQLite adapter принимается, если:

- он возвращает `session.id`, `session.title` и `session.directory`;
- доступ read-only;
- ошибка одной записи не ломает весь результат;
- пустой title получает `Без названия` и диагностическое предупреждение;
- неизвестная версия схемы определяется явно;
- версия Kilo ниже 7.7.5 отклоняется с понятной ошибкой;
- работает на выбранных версиях VS Code и Kilo;
- не требует чтения текстов сообщений для построения списка;
- обновление можно выполнить вручную хотя бы через `Refresh`;
- формат и ограничения задокументированы.

На изолированной тестовой базе, содержащей менее 10 000 подходящих sessions, набор metadata сверяется с результатом официального CLI с фиксированным `--max-count 10000`. Расхождение ID, title, directory или фильтра root/non-archived блокирует реализацию до объяснения причины. На реальной базе CLI не используется для контроля полноты runtime-результата.

Если `session.directory` нельзя безопасно и достоверно прочитать, Step 1 в заявленном виде технически заблокирован. Подмена списка данными `Open Recent` недопустима.

## 6. UI и модель папок

Нужно подтвердить прототипом:

- удобство плоского списка папок с раскрываемыми нативными деталями;
- отображение длинных title и paths;
- сортировку по Kilo timestamp;
- вид папки `missing`;
- поведение для 100 папок и 1 000 диалогов;
- исключение `.code-workspace`, multi-root, remote URI и UNC-путей;
- строки действий `Open Here`, `Open in New Window` и `Open in File Explorer`.

## 7. Что не нужно исследовать сейчас

- VS Code `Open Recent`;
- ручной реестр проектов;
- summary и LLM;
- embeddings;
- тексты и semantic search по сообщениям;
- открытие конкретного диалога;
- локальный HTTP API Hub;
- сложную индексирующую базу.

## 8. Выход Discovery

Discovery завершён, когда заполнена таблица:

| Решение | Результат |
|---|---|
| Версия Kilo | 7.7.5+ при совместимой schema |
| Версия VS Code | Зафиксирована после SQLite packaging spike |
| Физический источник Kilo | Путь к `kilo.db` найден с учётом overrides |
| Безопасный read-only доступ | Подтверждён |
| `session.id` и `session.title` | Найдены и проверены |
| `session.directory` → local folder | Найдено и проверено |
| Timestamp для сортировки | Подтверждён или отклонён |
| Дочерние/архивные sessions | Надёжно исключаются по `parent_id`/`time_archived` |
| `.code-workspace`, multi-root, remote и UNC | Надёжно исключаются |
| SQLite runtime | WAL-safe read-only доступ и VSIX packaging проверены |
| Механизм Refresh | Повторное чтение проверено |
| Opening folders | Три действия проверены |

Только после этого можно зафиксировать parser/data adapter и оценить реализацию без большого риска.
