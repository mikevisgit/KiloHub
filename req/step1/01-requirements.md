# Требования Step 1

## 1. Цель

Показать в одном месте все локальные папки, в которых пользователь работал с Kilo Code, названия связанных обычных Kilo-диалогов и дать возможность открыть такую папку в текущем или новом окне VS Code либо в Проводнике Windows.

## 2. Определение результата

Результат — устанавливаемый `.vsix`, который автоматически строит представление по локальной истории Kilo.

Пользователь должен иметь возможность:

1. открыть Kilo Hub из Activity Bar;
2. увидеть только папки с Kilo-активностью;
3. увидеть плоский список имён папок;
4. раскрыть папку и увидеть полный путь, действия и названия связанных Kilo-диалогов;
5. открыть папку в текущем окне;
6. открыть папку в новом окне;
7. открыть папку в Проводнике Windows;
8. обновить данные из хранилища Kilo.

Ручного управления составом списка нет.

## 3. Правило включения папки

Папка отображается, если одновременно выполняются условия:

1. в локальном хранилище Kilo найден хотя бы один обычный, не архивный диалог;
2. диалог содержит достоверную связь с локальной папкой;
3. связь можно нормализовать до локального пути Windows.

Папка не отображается, если:

- Kilo-диалогов для неё нет;
- есть только запись VS Code `Open Recent`;
- папка открывалась в VS Code, но Kilo в ней не использовался;
- связь диалога с папкой не определена или неоднозначна;
- диалог связан только с `.code-workspace`, Remote SSH, WSL или Dev Container;
- папка расположена по UNC-пути.

Удалённая папка с сохранившейся историей Kilo остаётся в списке как `missing`, потому что Kilo-активность существовала. Пользователь не может удалить её из Hub в Step 1.

## 4. Модель данных представления

Структура должна отражать данные Kilo из текущего профиля и текущей установки VS Code, а не создавать независимый реестр:

```ts
type KiloFolder = {
  id: string;
  uri: string;
  name: string;
  available: boolean;
  lastKiloActivityAt?: string;
  conversations: KiloConversation[];
};

type KiloConversation = {
  id: string;
  title: string;
  updatedAt?: string;
};
```

Фактические поля и идентификаторы должны быть подтверждены Discovery. Если у диалога нет сохранённого названия, используется `Без названия`. Разные диалоги с одинаковым названием отображаются отдельно; дубликаты одной записи удаляются по достоверному идентификатору.

## 5. UI

### 5.1 Размещение

- отдельная иконка Kilo Hub в Activity Bar;
- нативное представление `Kilo Folders` в Side Bar;
- toolbar-команда `Refresh`;
- раскрываемые детали у каждого элемента папки.

`Kilo Hub` — контейнер, который открывается по иконке Activity Bar. `Kilo Folders` — заголовок представления внутри контейнера. `Refresh` нужен для ручного повторного чтения истории без перезапуска Extension Host.

Верхний уровень визуально является плоским списком папок, а не деревом каталогов. Для нативного раскрытия деталей используется `TreeDataProvider`, а не webview. Это сохраняет стандартное поведение VS Code и не требует HTML/CSS и отдельного обмена сообщениями.

### 5.2 Первый уровень: папка

- label: имя папки;
- description отсутствует: в свёрнутом состоянии отображается только имя папки;
- tooltip: полный путь, количество диалогов, последняя Kilo-активность при наличии;
- обычный клик раскрывает или сворачивает детали;
- visual state: отдельное отображение недоступного пути.

### 5.3 Раскрытые детали

Детали отображаются в следующем порядке:

1. полный локальный путь;
2. кликабельная строка `Open Here` с иконкой;
3. кликабельная строка `Open in New Window` с иконкой;
4. кликабельная строка `Open in File Explorer` с иконкой;
5. отдельные строки связанных Kilo-диалогов.

Команды открытия доступны только внутри раскрытых деталей. Inline-команд при наведении и команд контекстного меню у строки папки нет.

### 5.4 Диалог

- label: сохранённое название Kilo-диалога;
- description: дата последней активности, если она доступна и достоверна;
- tooltip: полное название и дата;
- клик не выполняет переход и не открывает конкретный Kilo-диалог.

### 5.5 Действия папки

- `Open Here`;
- `Open in New Window`;
- `Open in File Explorer`.

Команд `Add Folder`, `Remove from Hub`, `Import Recent` и `Copy Path` нет.

## 6. Функциональные требования

### FR-1. Чтение Kilo-активности

Hub в read-only режиме получает обычные локальные Kilo-диалоги текущего профиля текущей установки VS Code, их названия и привязку к папке. Hub не изменяет данные Kilo. Архивные диалоги не учитываются.

### FR-2. Группировка

Диалоги группируются по нормализованному локальному пути Windows. Одна папка отображается один раз и содержит все найденные для неё диалоги. `.code-workspace`, Remote SSH, WSL, Dev Container и UNC-пути не поддерживаются в Step 1.

### FR-3. Фильтрация

В список попадают только группы, содержащие минимум один валидный обычный Kilo-диалог. Текущая открытая папка сама по себе не является основанием для появления в списке.

### FR-4. Названия диалогов

Для каждого диалога отображается название из хранилища Kilo. Для пустого названия используется `Без названия`. Fallback не запускает LLM и не читает содержимое проекта.

### FR-5. Сортировка

Папки сортируются по дате самого последнего связанного диалога, новые выше. Диалоги внутри папки также сортируются по последней активности, новые выше. Элементы с известной датой располагаются перед элементами без даты; элементы без даты сортируются по имени.

### FR-6. Обновление

Источник Kilo читается при первом открытии Hub. Команда `Refresh` повторно читает источник, пересобирает группы и обновляет список. Автоматического отслеживания изменений в Step 1 нет.

### FR-7. Открытие в текущем окне

```ts
vscode.commands.executeCommand(
  'vscode.openFolder',
  folderUri,
  { forceReuseWindow: true }
);
```

Текущий Extension Host завершается при смене workspace. Это штатное поведение VS Code.

### FR-8. Открытие в новом окне

```ts
vscode.commands.executeCommand(
  'vscode.openFolder',
  folderUri,
  { forceNewWindow: true }
);
```

### FR-9. Недоступный путь

Если папка отсутствует, Hub показывает её как `missing`, сохраняет список названий диалогов и блокирует команды открытия с понятным сообщением.

### FR-10. Открытие в Проводнике

Для существующей папки команда `Open in File Explorer` открывает её через стандартный API VS Code. Для `missing` команда заблокирована с понятным сообщением.

### FR-11. Отсутствие собственного реестра

Hub не хранит пользовательский список папок. Источником истины при каждом обновлении являются данные Kilo. Допустим только технический кэш, который можно полностью удалить и восстановить из Kilo без потери пользовательских данных.

## 7. Нефункциональные требования

- локальная работа без сети;
- read-only доступ к данным Kilo;
- отсутствие телеметрии;
- отсутствие чтения содержимого файлов проекта;
- отсутствие LLM-вызовов;
- список из 1 000 диалогов не должен заметно блокировать Extension Host;
- чтение базы или файлов Kilo выполняется безопасно при работающем Kilo;
- повреждённая запись не ломает весь список;
- Step 1 поддерживает только Windows;
- минимальные версии VS Code и Kilo фиксируются после Discovery;
- при недоступности источника отображается стандартная понятная ошибка и остаётся возможность повторить чтение через `Refresh`;
- корректно прочитанные записи отображаются, повреждённые записи пропускаются;
- технические подробности ошибок пишутся в Output Channel `Kilo Hub`.

## 8. Граничные случаи

- один путь записан с разным регистром или separator на Windows;
- папка перемещена или удалена;
- один диалог не имеет title;
- один диалог не имеет связи с папкой;
- один диалог связан с `.code-workspace`, а не с папкой, и поэтому исключается;
- дубликаты диалогов;
- архивные диалоги исключаются;
- Kilo обновляет storage во время чтения;
- используется только текущий профиль текущей установки VS Code;
- Remote SSH, WSL и Dev Container URI исключаются;
- UNC path исключается;
- название содержит не-ASCII символы.

## 9. Критерии завершения

Step 1 готов, когда:

- `.vsix` устанавливается на поддерживаемой версии VS Code;
- Hub показывает папки, извлечённые из реальной локальной истории Kilo;
- папка без Kilo-диалогов не отображается;
- папка с одним или несколькими Kilo-диалогами отображается один раз;
- верхний уровень показывает плоский список имён папок;
- раскрытие папки показывает полный путь, три действия и названия всех связанных обычных диалогов;
- `Open Here` заменяет текущий workspace;
- `Open in New Window` создаёт отдельное окно;
- `Open in File Explorer` открывает папку в Проводнике Windows;
- missing path обработан без падения;
- данные Kilo не изменяются;
- отсутствуют ручное добавление, удаление и отдельный реестр папок;
- отсутствуют summary, LLM и поиск по содержимому диалогов.
