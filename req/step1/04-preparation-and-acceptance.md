# Подготовка и приёмка Step 1

## 1. Что нужно подготовить

### От владельца продукта

| Вопрос | Рекомендуемое значение |
|---|---|
| Рабочее имя | Kilo Hub |
| Extension ID | `<publisher>.kilo-hub` |
| Первая платформа | Windows |
| Минимальная версия Kilo | 7.7.5 |
| Источник списка | Только локальная история Kilo |
| Папки без Kilo-диалогов | Не показывать |
| Состав списка | Без ручного управления |
| UI | `Kilo Folders`: плоский список имён с раскрываемыми деталями |
| Обычный клик по папке | Раскрыть или свернуть детали |
| Действия папки | Открыть здесь, в новом окне или в Проводнике |
| Действие диалога | Только отображение title |
| Граница данных | Текущая локальная Kilo database/environment |
| Дочерние и архивные sessions | Не учитывать |
| Marketplace | Не требуется для первого локального VSIX |

Также нужны:

- версия установленного VS Code;
- точная версия Kilo Code;
- изолированная тестовая Kilo database/environment для безопасного исследования;
- несколько тестовых folders с реальными Kilo-диалогами;
- одна контрольная folder без Kilo-диалогов;
- диалог с изменённым title;
- архивная и дочерняя session для проверки фильтрации;
- session, которая будет удалена во время проверки `Refresh`;
- malformed fixture с пустым title для проверки defensive fallback;
- разрешение исследовать локальное хранилище Kilo строго в read-only режиме;
- publisher name и временная монохромная SVG-иконка.

Ключи LLM, API моделей и тексты исходных проектов не нужны.

Legacy task-файлы `globalStorage/kilocode.kilo-code/tasks/*.json` для Step 1 не нужны и не исследуются как fallback.

## 2. Среда разработки

- Node.js LTS;
- npm;
- VS Code Stable;
- установленная целевая версия Kilo Code;
- отдельный VS Code profile для smoke tests;
- `@vscode/vsce`;
- Git repository, если нужны история изменений и CI;
- SQLite-инструмент для read-only проверки `kilo.db` и официальный Kilo CLI как oracle в Discovery.

Нельзя проводить эксперименты, которые изменяют или мигрируют рабочую базу Kilo.

## 3. Блокирующие решения Discovery

До основной реализации нужно получить ответы:

1. Как надёжно определить путь к `kilo.db` с учётом environment overrides.
2. Как получить title.
3. Как безопасно прочитать `session.directory` и нормализовать его до локального пути.
4. Как применить фильтр `parent_id IS NULL AND time_archived IS NULL`.
5. Какая SQLite-библиотека обеспечивает WAL-safe read-only доступ и упаковку в Windows VSIX.
6. Как безопасно повторно прочитать данные для `Refresh`.
7. Как распознать и исключить `.code-workspace`, multi-root, remote URI и UNC-пути.

Все семь пунктов обязательны. Без них нельзя корректно отфильтровать записи, безопасно обновлять данные и выполнить главный критерий: показывать только локальные папки с обычными Kilo-диалогами.

## 4. Acceptance scenarios

### AC-1. Установка

Given чистый поддерживаемый VS Code profile с Kilo, when пользователь устанавливает `.vsix`, then Kilo Hub появляется в Activity Bar и не требует сети.

### AC-2. Папка с Kilo-активностью

Given Kilo storage содержит обычный диалог, достоверно связанный с локальной folder A, when Hub выполняет `Refresh`, then folder A появляется в плоском списке.

### AC-3. Папка без Kilo-активности

Given folder B существует и открывалась в VS Code, но связанного Kilo-диалога нет, when Hub выполняет `Refresh`, then folder B не появляется.

### AC-4. Названия диалогов

Given folder A связана с тремя обычными Kilo-диалогами, when пользователь кликает folder A, then видит полный путь, три действия и три соответствующих названия без summary и чтения файлов проекта.

### AC-5. Группировка

Given несколько диалогов связаны с эквивалентными вариантами одного Windows path, when данные нормализованы, then folder отображается один раз со всеми диалогами.

### AC-6. Обновление

Given в Kilo создан, переименован или удалён обычный диалог, when пользователь вызывает `Refresh`, then список отражает изменение без перезапуска VS Code. Если удалена последняя обычная root session папки, папка исчезает из списка.

### AC-7. Открытие в текущем окне

Given folder доступна, when пользователь вызывает `Open Here`, then текущее окно переключается на неё штатным механизмом VS Code.

### AC-8. Открытие в новом окне

Given folder доступна, when пользователь вызывает `Open in New Window`, then текущее окно остаётся открытым и появляется новое окно с выбранной folder.

### AC-9. Недоступная папка

Given folder удалена, но её Kilo-диалоги сохранились, when Hub обновляется, then folder остаётся в списке как `missing`, titles доступны, а команды открытия заблокированы и не приводят к падению.

### AC-10. Read-only

Given Hub прочитал и отобразил данные, when содержимое Kilo storage сравнивается до и после, then Hub не изменил диалоги, titles и связи с папками.

### AC-11. Нет ручного реестра

Given пользователь открыл Hub, then интерфейс не содержит команд добавления, удаления или скрытия папки, а состав списка определяется только Kilo data source.

### AC-12. Открытие в Проводнике

Given folder доступна, when пользователь вызывает `Open in File Explorer`, then папка открывается штатным механизмом Windows.

### AC-13. Фильтрация неподдерживаемых записей

Given Kilo storage содержит дочернюю или архивную session либо связь только с `.code-workspace`, remote URI или UNC-путём, when Hub выполняет `Refresh`, then такая запись не влияет на список папок.

### AC-14. Пустое название и сортировка

Given повреждённая запись диалога имеет пустой title, when папка раскрыта, then отображается `Без названия`, а предупреждение записывается в Output Channel. Если timestamps доступны, папки сортируются по самому новому связанному диалогу, а диалоги внутри папки — по убыванию активности.

### AC-15. Ошибка чтения

Given источник Kilo временно недоступен, when Hub выполняет чтение, then пользователь видит понятную ошибку, может повторить операцию через `Refresh`, а технические подробности записываются в Output Channel `Kilo Hub`.

## 5. Definition of Done

- Kilo data source и схема задокументированы;
- Kilo 7.7.5 поддерживается, а несовместимая версия отклоняется с понятной ошибкой;
- read-only доступ подтверждён;
- SQLite runtime упакован в VSIX и проверен при работающем Kilo;
- на изолированной тестовой базе с менее чем 10 000 подходящих sessions результат metadata-запроса совпадает с official CLI oracle;
- CLI oracle запущен с фиксированным `--max-count 10000` без автоматического увеличения;
- все обязательные acceptance scenarios пройдены;
- unit и integration tests проходят;
- TypeScript compile и lint проходят;
- `.vsix` собирается воспроизводимо;
- пакет установлен и проверен на чистом profile;
- папки без Kilo-диалогов не отображаются;
- titles отображаются из Kilo data source;
- пустой title отображается как `Без названия`;
- `Open Here`, `Open in New Window` и `Open in File Explorer` проверены;
- расширение не изменяет Kilo storage;
- отсутствуют ручной реестр, add/remove folder и импорт `Open Recent`;
- отсутствуют summary, LLM и поиск по текстам сообщений;
- исключение `.code-workspace`, multi-root, remote URI и UNC-путей описано в release notes.

## 6. Рекомендуемая стартовая конфигурация

- только Windows;
- только локальные folders из текущей локальной Kilo database/environment;
- `Kilo Folders` с плоским верхним списком и раскрываемыми деталями;
- локальная `kilo.db` как единственный runtime-источник;
- ручной `Refresh` как обязательный механизм обновления;
- сортировка папок по timestamp самого нового диалога;
- обычный клик раскрывает или сворачивает детали;
- внутри деталей находятся полный путь и три строки действий;
- элементы диалогов пока только отображают title;
- технический кэш не используется до подтверждения проблем производительности.
