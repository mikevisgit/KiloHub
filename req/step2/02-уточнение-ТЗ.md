# Step 2 — уточнение ТЗ

## Назначение

Документ фиксирует последовательные решения пользователя по изменению дизайна Kilo Hub. Каждый ответ записывается до следующего вопроса и имеет приоритет над более ранней формулировкой канонического ТЗ Step 2.

## Правила ведения

- Один вопрос за один раз.
- Вопрос касается одного конкретного визуального или UX-решения.
- Принятый ответ записывается дословно по смыслу, без скрытого расширения scope.
- Если решение отменяет существующее требование, указывается заменяемый раздел канонического ТЗ.
- Нереализованные идеи не считаются принятыми требованиями.
- Открытие конкретного Kilo-диалога не добавляется: публичного local-session API Kilo Code 7.7.5 нет, пользователь отказался от upstream-изменения.

## Зафиксированная основа до уточнений

- Выбран один дизайн: «Монограммы».
- Представление Step 2 реализуется как `WebviewView` в существующем контейнере Kilo Hub.
- Текущая папка первая и помечена «Вы сейчас здесь».
- Диалоги остаются пассивным текстом; показываются до трёх последних.
- Источник данных остаётся metadata-only и read-only.
- Поиск, ручной реестр, telemetry, сеть, LLM и открытие диалога не добавляются.

## Принятые уточнения

Пока новых ответов после переноса дизайн-пакета в `req/step2/` нет.

## Открытый вопрос

Первый вопрос задаётся пользователю после проверки переноса и ссылок.
