# Step 2 — матрица тестирования и доказательств

## Назначение и статус

Матрица трассирует существенные требования Step 2 к обязательным автоматическим и ручным доказательствам. Production Webview реализован и имеет source/component/Extension Host evidence, но release не считается завершённым до exact VSIX, installed min/current gates, финальных review и пользовательского checklist на одном commit/hash.

Источники требований в порядке приоритета:

1. [Уточнение ТЗ](02-уточнение-ТЗ.md).
2. [Каноническое ТЗ](ТЗ%20реализации%20дизайна%20VSIX.md).
3. [Размерная спецификация](design-size-spec.md).
4. [Требования Step 1](../step1/01-requirements.md) для неизменённых данных, read-only поведения и команд.

Статусы:

- **ТЗ: зафиксировано** — требование и способ доказательства определены; это не результат production-теста.
- **Макет: есть offline evidence** — локальные проверки подтверждают reference-логику или структуру, но не Webview runtime.
- **Automated PASS** — указанный source/component/Extension Host test проходит на текущем production-кандидате; release gate повторяет его на итоговом commit.
- **Package pending** — source/build contract реализован, но exact VSIX/hash/install evidence ещё не получен.
- **Manual pending** — публичный API VS Code не даёт достаточного browser/GUI доказательства; нужен установленный VSIX и [ручной чек-лист](04-manual-acceptance-checklist.md).

## Review exit

Release-review считается завершённым только при одновременном выполнении условий:

- все обязательные области выше проверены на одном source commit и одном VSIX SHA-256;
- открытых `Blocker` и `High` findings: **0**;
- каждый `Medium` и `Low` имеет один явный disposition: **исправлен**, **не применим** либо **принятое ограничение**; для любого disposition приложены обоснование и evidence;
- после каждого исправления выполнено targeted re-review затронутой области и зависимых regressions;
- итоговые review-отчёты ссылаются на тот же commit, VSIX path/hash и результаты automated/manual evidence;
- незаполненный обязательный manual case означает `не проверено`, а не `пройдено`; pixel-level и субъективная визуальная приёмка остаются за пользователем по УТЗ-07.
