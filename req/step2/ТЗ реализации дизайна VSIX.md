[Скриншот 1](screenshots/image.png), [скриншот 2](screenshots/image2.png). Нормативный предыдущий scope находится в [req/step1](../step1/01-requirements.md); не переписывать историю задним числом.

Поэтому верх панели содержит ровно два видимых уровня: нативный заголовок VS Code и одну строку Webview. Нативный заголовок не входит в CSS-геометрию Webview.

## Полное поведение и точные тексты

1. Заголовок **«Мои папки с Kilo»**. Рядом небольшой значок информации без tooltip; доступное имя: **«Здесь собраны папки, в которых вы работали с Kilo. Чтобы вернуться к работе, выберите папку и откройте её.»** Постоянного пояснения нет.
2. Refresh — только **↻**, доступное имя **«Обновить список папок и диалогов из Kilo»**, без tooltip. Чтение при первом открытии и вручную; автоматическое наблюдение не добавлять.
3. Текущая папка, если включена по Kilo-истории, всегда первая. Подпись **«Вы сейчас здесь»** и устойчивый визуальный акцент независимы от раскрытия. Открытая в VS Code папка без Kilo-истории сама по себе в список не добавляется.
4. Нажатие плашки, в том числе названия, только раскрывает/сворачивает детали. Название и инициалы узнаваемы; название важнее даты. Полный путь показывается только при hover текста `.folder-name`, не всей `.folder-head` и не свободного места строки имени; отдельной строки пути нет. Знак, дата, current/missing, стрелка и остальная площадь head не показывают popup. При уходе с текста имени на них popup скрывается немедленно. Правило одинаково для свёрнутого/раскрытого состояния. Одинаковые имена различаются через эту подсказку и постоянный `aria-describedby` кнопки head без визуального popup по focus.
5. Действия в раскрытых деталях: **«Открыть в этом окне»**, **«Открыть в отдельном окне»**, **«Показать файлы папки»**, без tooltip по hover/focus. Последние два действия второстепенны. Постоянных пояснений нет. У доступной текущей папки обе команды «Открыть…» отсутствуют в DOM и Tab-порядке; остаётся только второстепенное «Показать файлы папки». У доступной нетекущей папки показаны все три команды.
6. Блок **«Последние диалоги»** не имеет подсказки. До трёх названий от нового к старому, каждое с новой строки, плотные интервалы, без маркеров, дат, кнопочных рамок, подчёркивания, hover-подсветки и постоянного пояснения. Видимая строка сокращается многоточием. В DOM у неё видимый сокращаемый span с `aria-hidden="true"` и visually-hidden span с полным title; поэтому accessibility tree содержит полный текст ровно один раз. Заголовок и названия не получают `tabindex`, `aria-describedby`, роль кнопки или иной отдельный Tab-stop; Enter ничего не открывает. Пустой title — «Без названия» по существующему defensive fallback.
7. Недоступная папка остаётся в истории: одна видимая пометка **«Папка не найдена»**, без подсказки статуса; полный путь доступен только по hover текста имени и через ARIA head. Не повторять предупреждение внутри. Все три действия отсутствуют в DOM и Tab-порядке; контейнер действий и место под него не создаются. История начинается сразу, без разделителя и отступов от отсутствующих кнопок. Это правило приоритетнее текущей папки, если оба состояния совпали; диалоги сохраняются. Это уточнение Step 2 заменяет прежнее отображение disabled-кнопок, не меняя исторический Step 1.

## Даты и сортировка

Источник — последняя достоверная Kilo-активность папки, а не время открытия папки. Относительная дата видна на свёрнутой плашке рядом с названием и сохраняется при раскрытии. Подсказки даты нет ни в свёрнутом, ни в раскрытом состоянии.

Сначала отбрасывать отсутствующий, некорректный или будущий timestamp (включая позже текущего момента сегодня): **«Дата неизвестна»**. Не выдумывать дату. Для достоверного timestamp считать разность календарных дат в локальном часовом поясе, не полные 24 часа; переходы летнего времени не меняют число календарных дней.

| Дней | Отображение |
| --- | --- |
| 0 | Сегодня, чч:мм — 24-часовой формат |
| 1 | Вчера |
| 2–6 | N дня/дней назад |
| 7–13 | Неделю назад |
| 14–20 | 2 недели назад |
| 21–29 | 3 недели назад |
| 30–59 | Месяц назад |
| 60–364 | floor(дни / 30) месяцев назад |
| ≥365 | floor(дни / 365) лет назад; 1 — «Год назад» |

Склонение: последние две цифры 11–14 → дней/месяцев/лет; иначе последняя цифра 1 → день/месяц/год, 2–4 → дня/месяца/года, остальные → дней/месяцев/лет. Месяцы и годы приблизительные; точный timestamp используется для сортировки, отдельный tooltip даты не показывается. Время в видимой подписи — только сегодня. При актуализации отображения учитывать смену локального дня; это не дополнительное чтение БД.

После текущей папки: достоверные даты по убыванию точного timestamp, неизвестные после известных по имени. При равных датах — имя, при равных именах — стабильный нормализованный путь/ID. Диалоги также по timestamp, неизвестные после известных, затем title и ID. Отображаемый текст относительной даты не использовать для сортировки. Простое открытие не меняет активность. Полный список папок сохраняется, сокращаются только показанные диалоги.

## Аккордеон, движение, клавиатура

Принято по команде выполнить все правки: одновременно раскрыта не более одной папки; повторное нажатие сворачивает её, нажатие другой сворачивает предыдущую. Плавное раскрытие/сворачивание длительностью **320 мс**, вдвое медленнее первоначальных 160 мс. Быстрые повторные нажатия сохраняют последнее намерение пользователя, включая сворачивание повторным нажатием. При изменении высоты компенсировать прокрутку относительно выбранной плашки, по возможности не уводить её из-под курсора. Если начало деталей вне видимой области — только минимальная необходимая прокрутка, без прыжка наверх. Край списка ограничивает компенсацию; нельзя гарантировать невозможное удержание координаты. При reduced motion движение отключить, компенсацию положения сохранить.

Плашка доступна по Tab, Enter/Space управляют раскрытием; aria-expanded и aria-controls согласованы с деталями. Скрытые детали исключены из порядка фокуса. После сворачивания не оставлять фокус внутри скрытого блока. Все команды имеют доступные имена и видимый focus. Tooltip закрывается Escape и следует единому доступному правилу ниже. Пассивные названия не имеют роли кнопки и не становятся Tab-stop. Не полагаться на цвет для текущего/missing. В узкой панели нет горизонтальной прокрутки, длинное имя папки переносится, диалог сокращается. Проверить 260/320/400 px и масштаб 200%.

## Единственная подсказка полного пути по УТЗ-10

Единственный visual owner и anchor: текст `.folder-name`, а не вся `.folder-head`. Hover/focus info/refresh/actions/head вне текста имени/date/mono/history/conversations/current/missing/стрелки не показывает popup. Нативные `title`-подсказки также запрещены. Focus любого элемента сам по себе не показывает и не удерживает tooltip.

Видимость определяется только `sourceHovered && !dismissed` для текста имени. Hover показывает tooltip **немедленно**, без задержки; leave скрывает немедленно, без grace, даже при focus на head. Переход к имени другой папки скрывает прежний popup. Попадание координат `pointermove` внутрь или на границу видимого popup скрывает его в том же событии, включая owner под popup, и удерживает `dismissed` до настоящего leave/reentry текста имени.

`Escape` скрывает popup немедленно и подавляет повторный показ до настоящего leave/reentry текста имени. Focus не снимает и не удерживает подавление. Сохраняется УТЗ-09: popup не содержит интерактивных потомков, имеет `pointer-events:none`, не перехватывает клики и не входит в Tab-порядок.

У каждой папки свой fullpath tooltip-узел со стабильным DOM `id`, текстом и `role="tooltip"`; одновременно видим не более одного. Кнопка `.folder-head`, а не текстовый hover owner, постоянно связана с полным path через `aria-describedby`, созданный до focus и неизменный при показе/скрытии. Скрытое состояние задаётся `hidden`; screen reader получает description без визуального popup. `.folder-name` не получает отдельного Tab-stop. Текст задаётся безопасно через `textContent`. Accessible name head содержит имя и видимые current/missing/date-состояния, description содержит полный путь. Info/refresh/actions сохраняют доступные имена без tooltip. Пассивные названия диалогов не получают `tabindex` или `aria-describedby`: полный текст постоянно доступен по правилу пункта 6.

Popup позиционируется после измерения текста `.folder-name` и popup: предпочтительно под текстовым owner по его левому краю, при нехватке места — над ним; координаты ограничиваются внутренним отступом **8 CSSpx** там, где геометрия физически помещается в viewport. Размеры: `max-width:min(330px, calc(100vw - 16px))`, `max-height:none`, перенос `overflow-wrap:anywhere`, `overflow:visible`. Внутреннего height clipping и недоступной прокрутки нет. Очень длинный popup может быть физически обрезан границей Webview; полный текст остаётся доступен через постоянный `aria-describedby` кнопки `.folder-head`. На `scroll`, `resize`, изменении текста и смене масштаба позиция пересчитывается; host-overlay за границами Webview не добавляется.

## Соразмерность UI VS Code

**Полная нормативная размерная спецификация:** [все размеры, отступы, типографика и ограничения эталона монограмм](design-size-spec.md). Приложение является частью этого ТЗ; таблица ниже — краткая сводка. При реализации использовать также подробные правила каскада, content-dependent высот, tooltip и отличий контрастной темы из приложения.

Базовый размер сопоставлен с [реальным Step 1](screenshots/kilo-hub-step1-scale-reference.png),2539×1445. Это evidence нативного масштаба, не визуальный эталон Step 2. Пиксели снимка не являются CSSpx; DPI/zoom неизвестны. Нормативные размеры — в приложении.

Единая база **B = `var(--vscode-font-size, 13px)`**, семейство `var(--vscode-font-family, 'Segoe UI', Arial, sans-serif)`, обычное начертание `var(--vscode-font-weight, 400)`. Размеры определяет последний общий файл `scale.css`, подключённый в HTML монограмм; демо-палитры не переопределяют B. При интеграции не подменять базу шрифтом редактора кода (`editor.fontSize`). Имена/заголовки — 600, буквы крупных монограмм — 700; обычный текст сохраняет UI-weight.

| Элемент | Размер монограмм | Пример B13 |
| --- | --- | --- |
| Действия, диалоги, tooltip, статус | B | 13px |
| Дата и current/missing-пометки | 12/13B | 12px |
| Имя папки | 16/13B | 16px |
| Заголовок списка | 15/13B | 15px |
| Знак / его буквы | 36/13B / 15/13B | 36px / 15px |

Line-height: имена и заголовок списка 1,3; обычный текст/даты/действия 1,4; диалоги 1,55; tooltip 1,45; буквы знака 1. Padding действий — 4/13B вертикально и 8/13B горизонтально. Диалоги не разделять дополнительными вертикальными полями. Начертание и умеренные размеры имени выделяют папку, а не уменьшают окружающий текст. Сохраняются округлые карточки и мягкие цветные знаки монограмм. Толщина рамок, контуры фокуса и форма углов остаются отдельными стилевыми величинами, а не компенсацией DPI.

На ширине панели 260/320/400 CSSpx не вводить media-уменьшение шрифтов/знаков. `min-width:0` у текстовой области, перенос длинного имени папки, однострочный ellipsis диалога, перенос текста кнопок и вертикальная прокрутка при нехватке высоты. Высота 790px в локальном стенде — только рамка просмотра, в Webview использовать доступную высоту секции и не отнимать место у соседнего Explorer. При zoom не вводить inverse-scale или дополнительные коэффициенты DPI. Проверить baseline 13/16/20px и 200% zoom в реальном окружении; статическая арифметика ширин не заменяет рендер.

## Темы и состояния

Компоненты используют `--vscode-sideBar-background`, `--vscode-sideBar-foreground`, `--vscode-descriptionForeground`, `--vscode-sideBar-border`, `--vscode-list-inactiveSelectionBackground/Foreground`, `--vscode-badge-background/foreground`, `--vscode-button-background/foreground`, secondary и hover варианты, `--vscode-focusBorder`, `--vscode-contrastBorder`, `--vscode-contrastActiveBorder`, `--vscode-disabledForeground`, `--vscode-editorWarning-foreground`, `--vscode-font-family` с fallback. [Официальное описание Webview и тем](https://code.visualstudio.com/api/extension-guides/webview#theming), [справочник цветов](https://code.visualstudio.com/api/references/theme-color). В интеграции не подключать `demo-themes.css`: значения поставляет редактор. Оригинальная пастельная палитра монограмм — визуальный reference; в текущей теме использовать контрастные семантические цвета, не принудительную светлую тему. Не подавлять forced colors.

Обязательная theme-приёмка выполняется на встроенных theme IDs **Default Dark Modern**, **Default Light Modern**, **Default High Contrast** и **Default High Contrast Light** в минимально поддерживаемой версии 1.105.1 и в версии, которой собирается release candidate; фактические `data-vscode-theme-id` и версии записываются в evidence. Для normal/hover/current/missing/focus/tooltip проверяются фактически образованные пары foreground/background: обычный текст не менее 4,5:1, крупный текст не менее 3:1, важные границы и focus не менее 3:1. Смена каждой темы применяется без reload и не меняет folder→color-group. В сторонних темах критерий best effort: только семантические `--vscode-*` tokens и алгоритм чёрных/белых инициалов, читаемый текст и видимый focus без hardcoded полной поверхности; универсальная гарантия 4,5:1 для произвольного theme extension не заявляется.

Состояния сохраняют понятный статус, не расширяют продукт:

- Первое чтение: «Загружаем папки…», aria-busy; блокировать повторный refresh.
- Успешный пустой список: «Здесь пока нет папок с диалогами Kilo». Refresh доступен; не предлагать ручное добавление.
- Обновление: предыдущий список остаётся, «Обновляем список…», aria-busy; исключить параллельные запросы.
- Ошибка первого чтения: «Не удалось загрузить папки. Попробуйте обновить список». Технические детали — Output Channel Kilo Hub.
- Ошибка refresh: прежний список остаётся, «Не удалось обновить список. Показаны ранее загруженные данные». Не выдавать его за свежий.
- missing: по правилам выше; это не ошибка всего источника. При успешном refresh исчезнувшие sessions и опустевшие папки удаляются из представления.

Эти состояния обязательны будущей реализации; основной HTML показывает нормальный список и missing, не имитирует подключение к БД.

### Матрица действий и host-проверок

| Состояние папки | Действия в DOM и Tab-порядке | Допустимые сообщения host |
| --- | --- | --- |
| Доступная, не current | Все три действия | `openHere`, `openNewWindow`, `revealInExplorer` |
| Доступная current | Только «Показать файлы папки» | Только `revealInExplorer`; обе команды открытия отклоняются |
| Missing, включая current+missing | Нет действий и actions-контейнера | Все три действия отклоняются |

Host проверяет эту матрицу заново по текущему snapshot, а не доверяет скрытию кнопки в DOM. Неизвестный/stale ID, несовпавшее состояние, неподдерживаемый тип сообщения и путь вне snapshot отклоняются без выполнения команды.

## Определение текущей папки

Current folder существует только для обычного single-folder local workspace. Resolver выполняется host-частью и возвращает нормализованный folder ID либо `null`:

1. Требуется ровно один элемент `vscode.workspace.workspaceFolders` и отсутствие `vscode.workspace.workspaceFile`. Тем самым исключены empty window, multi-root, untitled/saved `.code-workspace`, даже если в файле сейчас одна папка.
2. URI единственной папки должен иметь scheme `file`; отклоняются Remote/WSL/Dev Container и любые иные schemes. `fsPath` должен пройти существующую Step 1-нормализацию поддерживаемого абсолютного локального Windows drive path. UNC, namespace/device, drive-relative, относительный, malformed и разрешающийся через reparse/mapped path в UNC путь исключаются по существующим правилам безопасности.
3. Полученный case-insensitive canonical key сравнивается с folder ID уже загруженного host snapshot. Совпадение ровно с одной карточкой делает её current; отсутствие совпадения не добавляет новую карточку. Неоднозначное совпадение даёт `null`, а техническая причина записывается в Output.
4. Resolver вычисляется при создании view, при `onDidChangeWorkspaceFolders`, после успешного refresh и перед host-валидацией действия. Изменение workspace пересортировывает и обновляет current/actions из последнего корректного in-memory snapshot **без чтения БД**. Чтение Kilo выполняется только при первом открытии и явном refresh. Ошибка refresh сохраняет прежний snapshot, но current для него пересчитывается по текущему workspace.

## Формирование инициалов монограммы

Инициалы содержат ровно один или два Unicode grapheme clusters и зависят только от отображаемого имени папки:

1. Нормализовать имя в Unicode NFC и убрать краевой Unicode whitespace. Разделить его на слова по последовательностям символов, не относящихся к `Letter`, `Number` или `Mark`; пустые части и части без единого `Letter`/`Number` отбросить. Grapheme clusters выделять `Intl.Segmenter('ru', { granularity: 'grapheme' })`.
2. При двух и более словах взять первый grapheme первого и последнего слова. При одном слове взять первые два grapheme этого слова; односимвольное слово даёт один.
3. Привести выбранное к верхнему регистру фиксированной локалью `ru-RU`, снова сегментировать и оставить первые два grapheme, чтобы расширение регистра не нарушало предел.
4. Если имя не дало ни одного `Letter`/`Number`, повторить алгоритм для basename нормализованного полного пути. Если и он не дал результата, показать один символ `?`.

Пробелы, дефисы, подчёркивания и emoji сами по себе не становятся инициалами; буквы любых письменностей и цифры допустимы. Алгоритм детерминирован, не зависит от темы, цвета, current/missing, порядка карточек или доступности пути. Полное имя остаётся текстом рядом, поэтому монограмма не является единственным доступным обозначением.

## Устойчивые 16 цветовых групп значков

**Актуальное решение:** единая мягкая16цветовая система во всех четырёх тематических панелях, включая original. Предыдущее временное исключение original отменено; его понравившиеся пастельные заливки стали опорными для общей палитры. Обычные темы не имеют видимых рамок значков; рамки карточек сохраняются.

Принято в UX26. Цветовая группа относится только к монограмме/значку, не к карточке, названию или действиям. Один путь имеет одну группу в монограммах; current, missing, refresh, раскрытие и сортировка не входят в ключ. Настройки цветов, хранение таблицы соответствий и дополнительные команды не нужны. Цвет не является единственным признаком состояния.

### Нормализация и группа

Общий эталон — `variants/folder-colors.cjs`. В пределах текущего scope допускается только абсолютный локальный путь вида `D:\каталог`; UNC, namespace и относительные пути возвращают null, не получают вымышленного ID. Это не новая проверка доступности файлов и не расширение discovery Step1. В production использовать host-путь из существующего discovery и согласовать тот же ключ с его нормализацией.

1. Заменить `/` на `\`. Сохранить корень диска; повторные разделители и компоненты `.` пропустить, `..` снять предыдущий компонент. Выход выше корня отклонить.
2. Отклонить управляющие символы, `< > " | ? *`, двоеточие внутри компонента, компоненты с конечной точкой/пробелом. Не обрезать путь через trim и не разрешать его относительно cwd. Завершающие разделители вне корня удалить.
3. Привести весь ключ к нижнему регистру через JavaScript `toLowerCase()`. Unicode не нормализовать отдельно. Это регистронезависимый ключ текущего Windows-scope, не обещание идентичности case-sensitive каталогов.
4. FNV-1a по UTF-16 code units: начальное беззнаковое h=2166136261, на каждый `charCodeAt(i)` выполнить `h=Math.imul(h ^ code,16777619) >>> 0`; группа `h % 16` (0–15). Это устойчивое распределение, не уникальный идентификатор папки. Переименование/перемещение может изменить группу.

Полный путь для tooltip и цвета берётся из одного `data-path`/host DTO; отображаемое имя и позиция не хэшируются. Некорректный путь не получает цветовую группу; применяется нейтральный badge fallback. Отсутствующая на диске папка с корректным сохранённым путём сохраняет группу.

### Палитра и контраст

**Вразброс, но устойчиво:** после `slot=h%16` использовать фиксированную перестановку `slotOrder=[1,6,12,9,15,5,2,13,8,0,10,3,14,7,11,4]`; индекс цвета=`slotOrder[slot]`. Hue, светлая заливка и оттенок инициалов берутся по одному этому индексу. Состав16цветов не изменён. Перестановка одна для всех тем и дизайнов, не вычисляется заново при refresh.

Последовательность слотов0–15: персиковый → мятный → лавандовый → голубой → розовый → травяной → песочный → лиловый → бирюзовый → красноватый → синий → жёлтый → пурпурный → зелёно-мятный → индиго → лаймовый. Чередуются тёплые/холодные и разные семейства, как в исходном mint→peach→lavender→blue. У последовательных demo-слотов кратчайший разрыв hue не меньше60°, но это арифметический ориентир, не доказательство зрительной различимости.

Демонстрация раньше выглядела градиентом потому, что fixtures покрывали слоты0–15 по порядку, а палитра была спектральной. Переименование путей, смена дат и сортировка по цвету не нужны и не выполняются. Сохраняется current-first, затем реальная активность. Для произвольных соседних путей одинаковые/близкие цвета возможны: не перекрашивать папку вслед за её соседями. Эта однократная смена таблицы принята пользователем; дальнейшее соответствие остаётся детерминированным.

Индексы базовой палитры 0–15 имеют hue в градусах: **0,20,38,55,76,100,130,155,175,195,215,235,255,275,300,330**. Направления: красный, терракотовый, охристый, жёлтый, лаймовый, травяной, зелёный, мятный, бирюзовый, голубой, синий, индиго, фиолетовый, лиловый, пурпурный, розовый. Это группы оттенков, не обещание уникального зрительного распознавания.

Точные светлые RGB-заливки по индексам базовой палитры0–15: `#efd9d9`, `#f4deca`, `#eee1ca`, `#eee8ce`, `#e5e9d1`, `#dce8d0`, `#d3e9d9`, `#d1e9e1`, `#d2e8e7`, `#d5e7ed`, `#d8e3f1`, `#dde0f2`, `#e5ddf5`, `#eadcf0`, `#eedbed`, `#f0dbe4`. Peach/mint/blue/lavender точно сохраняют прежние исходные заливки; остальные подобраны близкими по мягкости. Это reference исходного эталона до d1ef061, расширенный до16групп.

В демо вычисляется фактический background панели через theme tokens; rgba композится с предками. Относительная sRGB-яркость>0,35 выбирает светлые заливки выше; иначе HSL(h,24%,28%). Инициалы HSL(h,28%,25%) в light или HSL(h,28%,90%) в dark. HSL округляется до RGB; если контраст инициалов к заливке<4,5:1, выбрать чёрный/белый с большим контрастом. Фон знака не зависит от current/missing и не обесцвечивается из-за статуса.

В обычных original/light/dark `--folder-border:transparent`: резерв1px внутри прежних размеров остаётся, видимой обводки нет. Контраст заливки к поверхности/рамки≥3 в этих темах не требуется. НЕ удалять рамки карточек, текущий акцент и текстовые пометки.

В HC-dark/HC-light читаемость приоритетна: если контраст заливки знака к фактическому фону плашки≥3:1, граница также transparent; иначе граница1px чёрная/белая с большим контрастом к поверхности. Режим распознаётся по demo-contrast либо классам/атрибуту theme-kind высококонтрастного Webview. Forced-colors использует Canvas/CanvasText и системную границу без подавления forced-color-adjust. Если computed цвет не поддерживается (не rgb/rgba), fallback Canvas/CanvasText, в обычном режиме граница transparent, в HC — CanvasText. Группа остаётся прежней. Реальное переключение тем и пользовательские темы проверять в VS Code отдельно.

Обработчик наблюдает изменения class/style/theme-kind у документа и предков, media forced-colors/color-scheme и возврат фокуса; пересчитывает оттенки без изменения path→group. В production проверить обновление реальной темы VS Code и произвольных пользовательских тем; локальные арифметические проверки не являются доказательством браузерной доступности. При нестандартных темах/нарушениях зрения группы могут восприниматься одинаково.
