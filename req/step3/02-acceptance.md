# Step 3: проверка и приёмка

## Обязательные проверки

| Область | Что доказать |
| --- | --- |
| Discovery и стек | Зафиксированы версия/commit источников, схема, ограничения provenance, механизм сверки удалений; стек явно согласован до реализации базы. |
| Смешанный формат | DB-09: пустые новые таблицы не вызывают отказ; записи альтернативного формата у допустимых sessions блокируют публикацию полного индекса. Last-good сохраняется, удаление не имитируется, новые payload не импортируются. |
| Изоляция данных | Попытка записи в Kilo отвергается; миграции/FTS/очистка возможны только в Hub; совпадение путей/идентичности отвергается до записи. |
| WAL | Чтение committed изменений работающего источника, busy retry, короткие транзакции, освобождение connections без checkpoint источника. |
| Отбор | Только root/non-archived, user text без synthetic/ignored; assistant/tool/file/compaction исключены; смешанный немаркированный текст не очищается эвристически. |
| Полнота | История старше 90 дней, диалоги за пределами трёх последних, рестарт первой подготовки, bounded batches без молчаливого усечения. |
| Изменения | Правка part при неизменном session.time_updated, удаление part/message/session, архив/разархив, исчезновение последней session папки. |
| Курсоры | Повтор события, gap/reset sequence, пропущенный poll, импорт без ожидаемого журнала, замена источника; reconciliation исправляет расхождение. |
| Горячий путь целостности | DB-10: повторные поиски того же проверенного поколения не вызывают quick_check; первое открытие/новое поколение/ошибка/подмена файла требуют проверки. Alias/sidecar/source guards и проверка владельца не обходятся кэшем. |
| Инкрементальное обновление | SYNC-08: изменение одного диалога не вызывает чтения/перезаписи текстов остальных. Полная сверка находит незажурналированное изменение, но не переписывает неизменные строки. |
| Прогресс при активном Kilo | Изменение источника между каждой порцией не сбрасывает завершённые диалоги; готовая часть доступна поиску с incomplete. После прекращения поступления изменений индекс сходится, включая новые IDs до прежнего курсора и restart. Неполная запись отдельного диалога не видна. |
| Ошибки | Частичная выборка не удаляет данные; busy/нет файла/нет прав/несовместимость/disk full не повреждают последний индекс; backoff и автоматическое восстановление. |
| Несколько окон | Нет конкурирующих миграций/двойной бесконтрольной индексации; crash владельца записи восстанавливается; область профилей подтверждена. |
| Автозапуск | Синхронизация работает при закрытой панели; после выхода из VS Code не остаётся отдельной службы. |
| Поиск | AND токенов по полям одной папки, подстроки, NFC/case/ё, минимум 3 Unicode code points в каждом токене, пунктуация, буквальные SQL/FTS-символы, отсутствие поиска по path. Короткий токен отклоняется до обращения к индексу на host; прежний запрос/выдача сохранены, показано пояснение. |
| Ранжирование | Current только при совпадении; все слова имени выше title-группы, затем совпадения с необходимым текстом реплик; стабильные tie-breakers. |
| UI поиска | До Enter список неизменен; черновик не применяется при sync; крестик/Escape/пустой Enter сбрасывают; reload не сохраняет запрос. |
| Выдача | Поиск старого диалога/реплики находит папку, но показывает обычные три последних; нет цитат и пометок причины совпадения. |
| Фоновые результаты | Отмена/устаревшая revision не затирает свежую; focus/expansion/scroll сохраняются либо безопасно восстанавливаются. |
| Плюсик | Выбор существующей папки, отмена, unsupported/missing, текущая папка, forceReuseWindow; нет создания каталогов/ручного реестра. |
| Текущая без истории | OPEN-04/05: первая временная карточка с отметкой и единственным пояснением внутри, без даты/действий/истории; возникает также при открытии средствами VS Code. Не записывается как история, не появляется в других окнах; фильтруется по имени. |
| Переход временной карточки | Смена workspace, reload, первый диалог, удаление/архив последнего диалога, потеря доступности: нет дубликатов, фиктивных sessions и потери focus в скрытый DOM. При неполном импорте/ошибке неизвестность не выдаётся за отсутствие истории. |
| Tooltip | Только info/plus/name-path; name hit area не равна карточке, геометрическое скрытие и Escape, keyboard/ARIA без лишних Tab-stop. |
| Accessibility | NVDA, keyboard, focus, inert, ограниченные live announcements, 4 встроенные темы/forced colors, 260/320/400 и 200%. |
| Security | XSS/SQL/FTS payloads, CSP, отсутствие сети, raw реплик в Webview/logs/VSIX и входных путей команд от Webview. |
| Производительность | Измерять первоначальное построение, поиск и обновление отдельно. Первоначальные 259 s приняты пользователем при фоновом выполнении; ускорение пакетирования не требуется само по себе. Проверить отсутствие блокировки UI, сохранение прогресса и допустимое отставание при backlog. Масштаб 1000 папок/10000 диалогов/100000 реплик — тест, не предел истории. |
| Без системного Node | Установленный VSIX индексирует и ищет в минимальном и актуальном VS Code без Node.js/npm/SQLite/Kilo CLI в системе. Одного запуска npm test недостаточно. |

## Примеры поиска

- Имя «Сайт», диалог «Корзина», реплика «Добавить оплату»: запрос «САЙТ оплат» находит папку; «сайт доставка» не находит.
- «заказ» в одном диалоге и «возврат» в другом той же папки: запрос «заказ возврат» находит папку.
- Слова в разных папках не объединяются.
- «е» и «ё» эквивалентны; «а», «аб» и «сайт по» не запускают поиск, сохраняют предыдущую выдачу и показывают пояснение; «сай» запускает. Проверить длину после NFC и Unicode code points, чтобы surrogate pair не считалась двумя символами.
- Совпадение только полного пути или assistant/tool текста не находит папку.
- Во время редактирования нового запроса фоновое обновление использует предыдущий применённый запрос.

## Release gate

Проверка DOC-01–04: README включён в exact allow-list, содержимое совпадает с `docs/extension-description.md`, в VSIX задан корректный README asset. Во вкладке Details установленного пакета отображается русское описание без «No README available», ссылки/изображения корректны; текст и manifest description соответствуют фактическим функциям и совместимости выпуска, без обещания будущих этапов. Проверка проводится на installed artifact, не только по наличию файла в репозитории.

1. Discovery завершён и ограничения записаны; согласование стека зафиксировано отдельно.
2. Unit/component/integration, typecheck/lint, security и migration/recovery проверки пройдены.
3. Независимое review: нет открытых Blocker/High; у остальных findings явный disposition и evidence.
4. Выпуск отдельной версии (предложение `0.3.0`, закрепить перед выпуском), два воспроизводимых clean package цикла и одинаковый SHA-256.
5. Exact allow-list и hashes проверяют bundles/icons/manifest и README для Details; source, tests, fixtures, личные данные, БД и sidecars не включены. Negative verifier проверяет отсутствие/устаревание README после изменения состава пакета.
6. Exact VSIX установлен в изолированные профили minimum/current VS Code, отдельно проверен сценарий без системного Node/npm.
7. В `handoff.md` записаны команды, source commit, путь, размер, checksum, ограничения и результаты. Пользовательская визуальная приёмка не подменяется тестами или source review.

## Статус

Полный набор проверок Step 3 пока **не завершён**. Выполненные целевые проверки и открытые замечания записаны в `handoff.md` и `reviews/`; они не заменяют общий release gate. Результаты `0.2.3` не являются evidence собственной базы, синхронизации или поиска Step 3.
